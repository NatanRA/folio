# Folio 0.9.1

Telegram no longer asks for an API ID and API hash. This build carries its own application
identity, so connecting Telegram is an ordinary sign-in: phone number, the login code Telegram
sends, and a two-step password if the account has one.

- **The API ID and API hash fields are gone.** Telegram issues that pair to the developer of a
  client rather than to each person using it, so asking for it made the Telegram section
  impassable for anyone who is not a registered Telegram developer. The identity now ships inside
  the app. Entering a pair by hand is still possible under "Use my own Telegram credentials" and
  overrides the built-in one.
- **Telegram connection failures say what went wrong.** Both failure paths reported the same
  sentence — "Couldn't initialise the secure Telegram connection" — whatever the cause, which left
  no way to tell a rejected identity from a network problem or a storage failure. The underlying
  reason is now shown.

The identity is read from an untracked file that is bundled at build time and never committed.
Builds made without one fall back to asking, exactly as before. See
[Telegram setup](../telegram-library.md).

## Downloads and installation

- **Android:** `Folio-Android.apk`, version 0.9.1 (55), Android 8+. Signed with the same
  certificate as the previous release; install over the existing app.
- **iPhone / iPad:** `Folio-iOS.ipa`, version 0.9.1 (14), iOS 17+. Unsigned ARM64 device package;
  sign and install with SideStore.

## Verification

- iOS, on an iPhone 17 Pro simulator running iOS 26.5, from a clean install: the Telegram section
  shows no credential fields and reaches "Phone number with country code", meaning TDLib accepted
  the bundled identity and completed `setTdlibParameters` against Telegram's servers. Both
  packages were confirmed to contain the identity file.
- That check needed a keychain entitlement granted to the simulator build. The release IPA is
  built unsigned for SideStore and so has no entitlements, and an app without them cannot write to
  the keychain — which is why the first attempt failed with a storage error rather than a Telegram
  one. SideStore re-signs with a profile that carries `keychain-access-groups`, so an installed
  build is unaffected; this only prevents testing sign-in on a simulator.
- **Signing in to a Telegram account was not performed.** A simulator cannot receive the login
  code, so the flow is verified as far as the phone-number prompt and no further.
- 44 iOS unit tests and 28 Android unit tests pass.
- Release-publisher checks: package versions, identities and archive integrity verified, and the
  Android signing certificate checked against the 0.9.0 asset before publishing.

Physical-device installation remains unverified.
