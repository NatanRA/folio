# Folio 0.9.0

Android and iOS now share one version number. Android moves from 0.8.8 and iOS from 0.3.8; both
are 0.9.0 from here on, and releases are tagged with a single version rather than a pair.

This release is mostly about getting logins onto the phone without typing them.

- **Scan to connect.** Run `swift scripts/make-pairing-code.swift` on your computer and it draws a
  QR code in the terminal holding a BookLore address, OPDS username and password. Point the
  phone's own Camera at it and Folio shows which server it points at and which account it would
  sign in as, then asks. Neither app requests camera access: the system camera does the scanning.
  Nothing is saved until the server accepts the credentials, and the password is never displayed.
  See [pairing](../pairing.md) — a code carries the password, so it is worth reading.
- **Password managers can fill the iOS logins.** The address, username and password fields across
  BookLore, KOReader sync and Notes sync now say what they hold, so iOS offers AutoFill on them.
  It never did before. The BookLore form also gains a Paste button that fills all three fields
  from one copied line, a link carrying credentials, or a JSON object.
- **Audiobooks appear in Continue.** Home only ever looked at e-book progress, so an audiobook
  could be a chapter in and still be missing from Home. Listening now counts, and Home offers the
  title you opened most recently rather than the first one it finds.
- **Telegram credentials can ship with the build.** Telegram issues an api_id and api_hash to the
  developer of a client rather than to each reader, so the app can carry its own. See below.
- The address field on iOS is labelled "Server address" instead of a URL-shaped placeholder, which
  iOS drew in link blue and which read as a filled-in value.
- Telegram is told this build's real version instead of a number hard-coded once and left behind,
  so the entry in your Telegram active-sessions list is accurate.

## Telegram credentials in this build

The plumbing ships, but **this build does not carry an identity**, so the Telegram section still
asks for an API ID and hash. To build one that does not, register an application at
my.telegram.org/apps, run `python3 scripts/set-telegram-identity.py`, rebuild, and the two fields
are replaced by an ordinary phone-number sign-in. Entering a pair by hand still works and
overrides whatever the build carries.

## Downloads and installation

- **Android:** `Folio-Android.apk`, version 0.9.0 (54), Android 8+. Signed with the same
  certificate as the previous release; install over the existing app.
- **iPhone / iPad:** `Folio-iOS.ipa`, version 0.9.0 (13), iOS 17+. Unsigned ARM64 device package;
  sign and install with SideStore.

## Verification

- iOS, on an iPhone 17 Pro simulator running iOS 26.5: the Telegram section goes straight to
  sign-in when a build carries an identity; the BookLore form shows the AutoFill fields and the
  Paste button; opening a pairing link shows the confirmation sheet with the server and account
  and no password; and Home shows "Continue listening" with a percentage for an audiobook in
  progress. 44 unit tests and two UI tests pass.
- Android: application and test sources compile and 28 unit tests pass, covering pairing-link
  parsing on both platforms. **The Android pairing dialog was not run**: no emulator or device was
  attached for this release, so it is verified by tests and compilation only.
- The pairing generator decodes its own output and refuses to print a code that does not scan back
  to the link it built.
- Release-publisher checks: package versions, identities and archive integrity verified, and the
  Android signing certificate checked against the 0.8.8 asset before publishing.

Physical-device installation remains unverified.
