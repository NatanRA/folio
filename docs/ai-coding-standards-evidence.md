# Research basis and limits

Revision: 2026-09-14.1. Sources checked on 14 September 2026.

This standard is a synthesis, not a transcription of one paper. Empirical findings motivate specific checks; the resulting instructions are engineering adaptations. None of these studies validates this exact skill, establishes a universal best AI workflow, or measures the current model in every project and language.

## AI-specific evidence

### Repository instructions: keep additions specific and evaluate their effect

Gloaguen et al., **Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?**, arXiv:2602.11988v2, June 2026 revision of the February preprint.

https://arxiv.org/abs/2602.11988v2

Read: abstract and full-text limitations and conclusion.

The study evaluates four coding agents on SWE-bench and CTXbench. Context files increased cost and steps; neither the marginal negative success-rate effect of generated files nor the marginal positive effect of developer-written files was statistically significant. Instructions were generally followed, while repository overviews were not helpful. Evaluation focused on Python and task resolution, not comprehensive security or maintainability outcomes.

**Adaptation:** keep the AGENTS.md addition short, preserve useful project-specific constraints, and link to the standard. Do not duplicate repository tours or claim that instruction length improves performance. This does not prove that our shorter reference or this skill will improve outcomes.

### Context-file maintenance and omitted quality requirements

Chatlatanagulchai et al., **Agent READMEs: An Empirical Study of Context Files for Agentic Coding**, arXiv:2511.12884v2, August 2026 revision of the November 2025 preprint.

https://arxiv.org/abs/2511.12884v2

Read: abstract, full-text conclusion and limitations.

The study characterizes 2,303 context files from 1,925 repositories. They evolve through frequent additions and often have difficult readability. Security and performance requirements appear much less frequently than testing and implementation instructions. This is descriptive evidence, not a controlled demonstration that adding security instructions prevents vulnerabilities.

**Adaptation:** explicitly cover relevant security and performance requirements, and keep the standard maintainable rather than continually accumulating rules.

### Package hallucinations: verify dependencies

Spracklen et al., **We Have a Package for You! A Comprehensive Analysis of Package Hallucinations by Code Generating LLMs**, USENIX Security 2025; arXiv:2406.10279v3, March 2025 revision.

https://arxiv.org/abs/2406.10279v3

Read: abstract and full-text discussion and conclusion.

The authors generated 576,000 samples using 16 models for Python and JavaScript and found nonexistent package recommendations, including repeated hallucinations. They discuss supply-chain abuse and mitigation. The paper explicitly notes that newer models appeared after the study and that its commercial-model coverage is limited. Its rates must not be presented as current rates for today's agents.

**Adaptation:** verify an unfamiliar dependency's exact name, intended source/publisher, version, and need before adding it. Verify unfamiliar APIs against installed source/types or version-appropriate official documentation. API verification is a related engineering precaution, not a direct experimental finding of this package study.

### Test adequacy: passing weak tests is insufficient

Liu et al., **Is Your Code Generated by ChatGPT Really Correct? Rigorous Evaluation of Large Language Models for Code Generation**, arXiv:2305.01210v3, October 2023 revision (EvalPlus).

https://arxiv.org/abs/2305.01210v3

Read: abstract and full-text conclusion.

Expanded HumanEval tests exposed incorrect generated programs that passed the original tests and affected model rankings. This is evidence about test adequacy in function-level synthesis benchmarks, not a direct experiment on modern repository agents, every type of integration test, or our exact testing policy.

**Adaptation:** establish expected results independently of the implementation, test relevant counterexamples and boundaries, reproduce nontrivial bugs, and select the appropriate integration or user-workflow check. Do not change tests merely to accommodate incorrect output.

### Productivity: measure the work and respect study dates

Becker et al., **Measuring the Impact of Early-2025 AI on Experienced Open-Source Developer Productivity**, July 2025 research report and associated paper.

https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/

Follow-up, **We are Changing our Developer Productivity Experiment Design**, 24 February 2026:

https://metr.org/blog/2026-02-24-uplift-update/

Read: both reports, including the follow-up's selection and measurement limitations. The early randomized study covered 16 developers and 246 tasks using early-2025 tools. The original page now explicitly says its historical result no longer reflects current productivity impact. The follow-up describes newer tools, selection effects, and problems measuring concurrent agent work; its estimates are not reliable evidence of a precise current speedup.

**Adaptation:** evaluate verified completion, rework, and actual time/cost where available. Neither cite the historical slowdown as a current claim nor assume that confidence, benchmark scores, or code volume establish productivity gains. This standard does not require automatic monitoring or added time tracking.

## Established engineering foundations

Eisty et al., **Ten Essential Guidelines for Building High-Quality Research Software**, arXiv:2507.16166v1, July 2025.

https://arxiv.org/abs/2507.16166v1

The ten guidelines cover planning, modularity, readability, version control, testing, review, documentation, reproducibility, performance when needed, and maintenance. Dependency injection is recommended where appropriate. There is no mandatory 30-line function limit.

Wilson et al., **Best Practices for Scientific Computing**, PLOS Biology 12(1):e1001745, 2014.

https://doi.org/10.1371/journal.pbio.1001745

Supports understandable code, small changes, reuse, automated tests, regression checks, profiling, documentation, and review. Its age does not invalidate these principles, but it does not address modern coding agents.

Wilson et al., **Good enough practices in scientific computing**, PLOS Computational Biology 13(6):e1005510, 2017.

https://doi.org/10.1371/journal.pcbi.1005510

Supports proportionate practices and reproducibility. Its roughly one-page/60-line function heuristic is contextual advice, not evidence for a universal cutoff.

## Practical synthesis, not experimentally proven rules

The specific policies on pure domain logic, boundary validation, owned shared state, missing-versus-zero semantics, multiple implementation paths, authorization and tenant checks, safe retries, avoiding speculative changes, and truthful completion reporting are engineering adaptations. They combine the user's objectives with established principles and observed AI failure modes. No study here independently proves each exact instruction.

Use linters, types, tests, security checks relevant to the change, and CI for executable enforcement. Instruction-file validation establishes structure and links only. Review real coding outcomes before claiming that this revision improves quality or speed. Revisit individual recommendations when newer evidence or observed failures warrant it; publication date alone is neither sufficient reason to accept nor reject a practice.
